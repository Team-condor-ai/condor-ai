## 2. Por qué llevaban dos días pendientes, y cómo se resolvió

No era olvido. El camino normal del CLI (`supabase link` + `db push`) pide la
**contraseña de la base**, que es distinta por proyecto y que Joaquín no tenía
a mano. Por eso quedaba siempre como "correr esto a mano en el SQL Editor", y
por eso se acumulaban.

La **Management API** no la necesita: se autentica con un Personal Access
Token de la cuenta y expone `POST /v1/projects/{ref}/database/query`, que corre
SQL arbitrario con permisos de dueño.

El token ya existe — el CLI de Supabase lo guarda en el **Credential Manager
de Windows** al hacer `supabase login`. Se armó
`~/.claude/herramientas/sbsql.py`, que lo lee de ahí. No deja copia del
secreto en disco y se actualiza solo si Joaquín vuelve a loguearse.

```
python sbsql.py --listar
python sbsql.py ylsqvmggycfijzfvguzq migracion.sql
python sbsql.py ylsqvmggycfijzfvguzq -c "select count(*) from clientes;"
```

Dos trampas que costaron tiempo y conviene no volver a pagar:

1. **El blob del Credential Manager son bytes UTF-8, no UTF-16.** Leerlo con
   el marshalling Unicode por defecto devuelve caracteres chinos
   (`扳彰づ㤴...`), no el token.
2. **La API está detrás de Cloudflare y responde `error code: 1010`** al
   User-Agent que manda `urllib` por defecto. Con cualquier UA de navegador o
   de curl, pasa. Lo confuso es que `curl` funcionaba y Python no, y el error
   no dice por qué.

Alcance hoy: cubre los proyectos de la cuenta principal (Cóndor ×2, Howden,
Veci). **Planeta Shop (`rufyosygsduljguegvpk`) vive en otra cuenta** y
necesita su propio PAT en `herramientas/tokens.json`.
